# City Insight Map · Енергія

Прототип для **Poltava Open Data Hackathon 1.0**, трек 2 «Енергетичний менеджмент та енергетична стійкість».
Внутрішній інструмент енергоменеджера громади: порівнює комунальні будівлі за споживанням на м², знаходить дефекти даних UMUNI й оцінює, де варто ставити нові сонячні станції (СЕС).

> Клас ефективності й базовий рівень у рішенні — **аналітична оцінка, а не офіційний енергетичний сертифікат**.

## 1. Проблема і користувач

**Користувач:** енергоменеджер громади (фахівець з енергомоніторингу, через якого проходять 311 об'єктів у UMUNI). Також керівники департаментів освіти й охорони здоров'я та УЖКГ.

**Проблема** (за ТЗ та інтерв'ю з енергоменеджером 19.11):
- дані про 311 будівель зібрані в UMUNI, але будівлі не порівнюються між собою за споживанням на м², базового рівня немає;
- якість даних ніхто не перевіряє: площа 1 м², координати 0,0, стрибки в десятки разів;
- генерацію СЕС доводиться дивитися, «заходячи в кожен об'єкт окремо»;
- станцію треба підбирати **під власне споживання**: продати надлишок заклад законодавчо не може, а сонце зараз покриває максимум ~30% споживання;
- ліміти на енергоносії ставлять «три останні роки + відсоток на тариф», без урахування моніторингу.

## 4. Архітектура

```
 XLSX UMUNI ──┬─ backend/data/*.xlsx (при старті)
              └─ POST /api/upload («Оновити дані»)
                        │
                        ▼
 import_umuni.py   розпізнає тип звіту за заголовками, рік і дату — з аркуша «Інформація»
                        │
                        ▼
 analytics.py      МВт·год, кВт·год/м², медіани, класи A–G, рейтинг, валідатор
 solar.py          PVGIS → площа даху, генерація, покриття, окупність   
                        │
                        ▼
 main.py (FastAPI) ── /api/* (JSON, CSV) + роздає зібраний фронтенд
                        │
                        ▼
 frontend/ (SvelteKit SPA, adapter-static) ── браузер енергоменеджера
```

Один процес, один порт (8000). Дані тримаються в пам'яті й перераховуються після кожного завантаження.

| Метод | Що повертає |
|---|---|
| `GET /api/summary` | зведення: роки, охоплення, медіани категорій, класи, кількість дефектів |
| `GET /api/buildings?category=` | будівлі з класом, місцем у рейтингу або причиною виключення |
| `GET /api/buildings/{id}` | картка будівлі з дефектами й медіаною категорії |
| `GET /api/defects` / `GET /api/defects.csv` | список дефектів даних (CSV — це `data-defects.csv`) |
| `POST /api/upload` | нове вивантаження UMUNI (XLSX) → перерахунок |

Інтерактивна документація API: `http://localhost:8000/docs`.

## 5. Запуск

### Docker Compose (рекомендовано, ~5 хв)
```bash
docker compose up --build
```
Відкрити http://localhost:8000. Папка `backend/data` підключена як том, тож завантажені файли зберігаються між перезапусками.

### Локально для розробки
Потрібні Python 3.12+ і Node.js 22.

```bash
# бекенд
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows; у Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000
```
```bash
# фронтенд (в іншому терміналі)
cd frontend
npm ci
npm run dev                     # http://localhost:5173, API — на :8000
```
Щоб побачити зібрану версію без Docker: `npm run build` у `frontend/`, після чого бекенд сам роздає її на http://localhost:8000.

## 6. Як оновити дані

Без розробника, без ручної переробки файлу:
1. **Кнопка «Оновити дані»** в інтерфейсі → вибрати XLSX, вивантажений з UMUNI («Характеристики будівель» або «Річний звіт використання ресурсів по будівлях»). Те саме через API: `curl -F "file=@звіт.xlsx" http://localhost:8000/api/upload`.
2. **Або** покласти XLSX у `backend/data/` і перезапустити сервер.

Тип звіту визначається за заголовками, рік і дата вивантаження — з аркуша «Інформація». Якщо за один рік є кілька файлів, береться новіший за датою створення. Усі показники, рейтинг і дефекти перераховуються автоматично.

**`data-defects.csv`** формує сам застосунок: `GET /api/defects.csv` (кнопка в інтерфейсі). Колонки: набір, будівля_id, будівля, поле, значення, правило, що_робити. Перед здачею файл зберігається в корінь репозиторію:
```bash
curl -o data-defects.csv http://localhost:8000/api/defects.csv
```

## 7. Відомі обмеження

- **2026 рік неповний** (вивантаження 11.11.2026, ~86% року). Базовий рік — 2025; 2026 використовується лише для пошуку стрибків, висновки за ним попередні.
- **Координати є лише в 34 з 311 будівель** (решта — 0,0). Для PVGIS без координат беремо центр Полтави; карта потребує геокодування.
- **Даних про наявні СЕС, інвертори й акумулятори в пакеті немає.** Модулі моніторингу показуємо на демо-даних з позначкою «ДЕМО-ДАНІ».
- **Тарифи й вартість монтажу СЕС — припущення** до уточнення з ментором; користувач може ввести власні.
- **Газ:** коефіцієнт 9,3 кВт·год/м³ (нижча теплота згоряння) — припущення, потрібно погодити.
- Реєстр лічильників (D2-04) ще не підключено, тому правило «ресурс з лічильником, але без споживання» поки не перевіряється.
- Загальне питоме споживання рахується з наявних енергоносіїв; якщо в будівлі не заповнено, наприклад, тепло, показник занижений (такі випадки видно в картці).
- Воєнні відключення, дистанційне навчання й генератори спотворюють споживання; валідатор формулює сигнал як «перевірити», а не як порушення.
- Входу за паролем у прототипі ще немає: запускати лише у внутрішній мережі.

## 8. Безпека й етика

- **Без ПІБ і телефонів.** Сирий файл «Інформація щодо впровадження СЕМ…xlsx» містить ПІБ і телефони відповідальних — його немає в репозиторії (`.gitignore`), і рішення його не використовує.
- **Без заводських номерів лічильників:** сирий `Лічильники.xlsx` також виключено.
- **Без даних про резервне живлення:** рішення не показує, які заклади мають генератори чи автономне живлення.
- **Клас A–G — не офіційний енергосертифікат**, а порівняння з медіаною аналогів.
- **Лише внутрішня версія** з розмежуванням доступу (ролі — у планах). Жодних ключів і паролів у репозиторії; налаштування — у `.env` за зразком [.env.example](.env.example).
- Пропуск у даних — це «немає даних», а не нуль: валідатор позначає, а не виправляє мовчки.
