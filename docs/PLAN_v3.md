# План v3 — «Ефективність СЕС комунальних об'єктів» (спільний контракт для всіх агентів)

Трек 2, кейс 2.2 «Сонячна генерація: потенціал і моніторинг СЕС» (+ частини 2.1 і 2.3).
Тепло, газ, вода — НЕ показуємо в інтерфейсі (лише імпорт/валідатор). Усе — про електроенергію і СЕС.

## Головна ідея
1. Головний екран — **мапа всіх комунальних об'єктів** (311 точок), колір точки = клас ефективності СЕС.
2. **K — коефіцієнт використання СЕС** = згенеровано ÷ спожито за період (день / місяць / рік).
   - K = 1,0 — скільки згенерували, стільки й спожили (ідеал).
   - K < 0,8 — **«Не вистачає»** (станція замала, докуповуємо з мережі).
   - 0,8 ≤ K ≤ 1,2 — **«Ефективно»** (збалансовано).
   - K > 1,2 — **«Надлишок»** (енергія лишається / пропадає — продати бюджетна установа не може).
   - Немає станції — **«Без СЕС»**; немає даних споживання — **«Немає даних»**.
   - Пороги 0,8 / 1,2 — константи в коді, налаштовуються, описані в METHODOLOGY.md.
3. **Дашборд** з фільтрами: ефективні / не вистачає / надлишок / без СЕС / немає даних, тип закладу, період.
4. **Картка об'єкта** — усі показники електроенергії та СЕС: к-сть панелей, потужність панелі (Вт), сумарна потужність (кВт), модель і потужність інвертора, к-сть акумуляторів × ємність модуля = загальна ємність, витрати (панелі, інвертор, акумулятори, монтаж, разом), K за день/місяць/рік.
5. **Фінанси й окупність** (якщо заповнені дані СЕС і вартість): витрачено на електроенергію з мережі (грн), заощаджено завдяки СЕС (грн), вкладено в СЕС (грн), окупність (років), прогрес окупності (%), помісячно.
6. **Мінімум тексту**: числа, іконки, кольори + підписи; пояснення — лише в підказках (Term) і в METHODOLOGY.md.
7. **Ролі** (за розділом 3 ТЗ) + публічний режим (розділ 6, «Безпека»; критерій «Прозорість»).

## Ролі (бекенд перевіряє роль, а не лише інтерфейс)
| id | Назва | Що бачить / може |
|---|---|---|
| `public` | Мешканець, журналіст, депутат (без входу) | мапа з типом/споживанням/потенціалом СЕС, зведені цифри громади, ефект інвестицій у СЕС (агреговано). **Без** акумуляторів, автономності, відключень, наявності СЕС по конкретних об'єктах |
| `energy_manager` | Енергоменеджер міста | усе; редагує дані СЕС і вартість будь-якого об'єкта; завантажує UMUNI |
| `data_admin` | Адміністратор даних UMUNI | усе на перегляд; завантаження UMUNI; якість даних |
| `department` | Управління освіти / охорони здоров'я | повні дані своїх категорій (освіта+садочки або охорона здоров'я), решта — як public |
| `facility_head` | Керівник закладу | повні дані **свого** об'єкта (обирає при вході), редагує дані СЕС свого об'єкта; решта — як public |
| `finance` | Фінансовий орган | фінанси/окупність/витрати всіх об'єктів, без акумуляторів і автономності |

Вхід: ПІБ, посада, роль (+ об'єкт для керівника, + управління для department), пароль.
Пароль — спільний демо-пароль з `.env` (`DEMO_PASSWORD`, у `.env.example` — заглушка). Бекенд видає підписаний токен (HMAC, `SECRET_KEY` з `.env`, у dev — згенерований), фронтенд шле `Authorization: Bearer`.

## API-контракт (додавати поля можна, перейменовувати — ні)
- `POST /api/auth/login` {full_name, position, role, building_id?, department?: 'освіта'|'здоров'я', password} → {token, user:{full_name, position, role, role_name, building_id, department}}
- `GET /api/auth/me` → user | 401;  `GET /api/auth/roles` → [{id, name, description, needs_building, needs_department}]
- `GET /api/ses?period=day|month|year&day=YYYY-MM-DD` → {demo, period, thresholds:{low:0.8, high:1.2}, totals:{objects, with_ses, effective, deficit, surplus, no_ses, no_data, gen_kwh, cons_kwh, k, capex_uah, saved_uah_year, grid_cost_uah_year}, items:[{id, name, address, category_short, lat, lon, precision, has_ses, k, k_class:'Ефективно'|'Не вистачає'|'Надлишок'|'Без СЕС'|'Немає даних', gen_kwh, cons_kwh, ses_kw, battery_kwh, capex_uah, saved_uah_year, payback_years}]} — для public: `has_ses/k/ses_kw/battery_kwh/capex` по об'єктах прибрані (null), totals лишаються.
- `GET /api/ses/{id}?day=` → {demo, building:{...}, ses:{panels_count, panel_w, total_kw, inverter_model, inverter_kw, battery_count, battery_module_kwh, battery_kwh, battery_kw, connected_kw, launched, source:'ДЕМО'|'введено'}|null, costs:{panels_uah, inverter_uah, batteries_uah, install_uah, total_uah}|null, k:{day, month, year}, k_class:{day, month, year}, energy:{day|month|year: {gen_kwh, cons_kwh, self_kwh, surplus_kwh, grid_kwh}}, finance:{tariff_uah_kwh, grid_cost_uah:{month, year}, saved_uah:{month, year, since_launch}, invested_uah, payback_years, payback_progress_pct}, monthly:[{month:1..12, gen_kwh, cons_kwh, k}], meters:{electricity, total, by_resource:{...}}, sem:{...}|null, can_edit:bool}
- `PUT /api/ses/{id}` {ses fields, costs fields} → оновлений об'єкт (ролі: energy_manager; facility_head — лише свій). Порожні поля = «немає даних».
- Старі ендпоінти (`/api/sites`, `/api/independence`, `/api/map`, `/api/solar`, `/api/forecast` …) працюють як раніше, але чутливі (акумулятори, автономність, відключення) — лише для авторизованих ролей.

## Інтерфейс (навігація)
`Мапа` (/, головна) · `Дашборд` (/dashboard) · `Об'єкти` (/objects, список) · `Нові СЕС` (/solar) · `Аналітика ▾` (Енергонезалежність, Споживання, Рейтинг, Якість даних, Оновити дані).
